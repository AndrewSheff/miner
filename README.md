# Miner

Технодемка — симулятор производственных цепочек в терминале на C.

Написан без игровых движков: управление данными, таймирование и рендер реализованы вручную поверх ncurses и POSIX API.

## Архитектурные решения

### Двойное хранилище: карта + коллекции

Здания хранятся одновременно в двух структурах с разными задачами:

```c
building *building_map[M_HEIGHT][M_WIDTH]; // O(1) поиск по позиции
building_array buildings;                  // итерация по всем зданиям
```

Карта нужна для мгновенной проверки: есть ли здание на конкретной клетке (используется при движении ресурсов и коллизиях). Коллекции — для обновления всех объектов в game loop без обхода всей сетки.

### Независимые таймеры на каждый объект

Каждое здание и каждый ресурс хранят время последнего действия:

```c
struct timespec ts; // внутри building и prop
```

В game loop сравнивается с `clock_gettime(CLOCK_MONOTONIC)`. Это позволяет каждому объекту работать на своём таймере независимо от других — печь не ждёт шахтёра, ресурсы движутся в своём ритме.

### Type mapping вместо switch-case

Связи между типами объектов задаются таблицами:

```c
prop_type    building_to_prop[BUILDING_TYPE_COUNT];  // шахтёр → руда
building_type prop_to_building[PROP_TYPE_COUNT];     // руда → печь
building_type key_to_building[KEY_COUNT];            // клавиша → тип здания
```

Добавить новый тип ресурса или здания — значит дописать строку в таблицу, а не искать все switch-case по коду.

### Динамические массивы с realloc

Коллекции зданий и ресурсов растут по мере добавления:

```c
arr->items = realloc(arr->items, arr->size * sizeof(building*));
```

При удалении — сдвиг элементов и `realloc` вниз. Никаких фиксированных лимитов на количество объектов на сцене.

## Производственная цепочка

```
ШАХТЁР → (руда) → ПЕЧЬ → (слиток) → СБОРЩИК → (товар)
```

Каждый ресурс знает своё целевое здание через таблицу `prop_to_building`. Достигнув нужного здания — поглощается и запускает его цикл.

## Управление

| Клавиша | Действие |
|---------|----------|
| `W` `A` `S` `D` | Переместить курсор |
| `1` | Поставить шахтёр |
| `2` | Поставить печь |
| `3` | Поставить сборщик |
| `B` | Режим конвейера |
| `R` | Удалить объект |
| `Q` | Выйти |

## Сборка

```bash
gcc collections.c building.c prop.c environments.c main.c -o main -lncurses
./main
```

или:

```bash
bash compile_debug.sh
./main
```

**Зависимости:** GCC, ncurses (`libncurses-dev` на Ubuntu/Debian).

## Структура

```
├── main.c            # Игровой цикл, ввод, ncurses
├── building.c/h      # Здания: создание, удаление, обновление
├── prop.c/h          # Ресурсы: движение, столкновения
├── collections.c/h   # Таблицы маппинга типов
├── environments.c/h  # Таймеры, размер поля, клавиши
├── enums.h           # Типы зданий и ресурсов
└── ncursescustom.h   # Движение курсора
```
